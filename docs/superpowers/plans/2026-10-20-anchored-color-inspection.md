# Anchored color inspection

Scope: replace preview-token modals, neutral-role-map modals, and palette bottom details with one shared click/tap popover. Solid dark surface, compact selected-color value, actual foreground/background pair, verified ratio, requirement, and margin. Use the most restrictive checked relationship and label it explicitly; decorative colors have no invented target. Keep full existing diagnostics inside an optional details section.

Architecture: ColorPopover uses native HTML popover controls for opening, dismissal, keyboard support, and focus navigation. Named CSS anchors, position-area and position-try-fallbacks handle all placement; no JavaScript coordinates or positioning listeners. A CSS viewport fallback handles older anchor-positioning support or insufficient room around a swatch. colorInspection builds a read-only summary from actual generated checks. ColorInfo renders the compact summary. Selection handlers pass the clicked element so no DOM guessing or global queries are required. Mobile uses a viewport-contained bottom panel.

Verification: model tests for actual pairs, theme isolation, no target for decorative roles, and truthful text/UI grades; lifecycle tests for focus/escape/outside click/anchor switching and cleanup; integration tests for all three entry points; full suite, type/build/PWA checks and bounded desktop/mobile browser QA. Existing precise source colors, generation, and exports remain unchanged.

Completed: 336 tests passed, one optional profiling test skipped; production build and PWA verification passed. Browser checks confirmed preview/palette/neutral entry points, light/dark data, keyboard access, Escape/close dismissal, CSS edge placement, and scrollable full role tables within the viewport. Palette checks match theme-qualified usage names, with a failing-then-passing regression for checked surface colors. Narrow-screen placement is handled by the base CSS viewport layout; no device emulation was available in the browser tools.
